## 1. Общие правила композиции

### 1.1. Обозначения

| Знак | Что значит |
|---|---|
| `UiName` | Компонент есть в `@/design-system`, используется как есть (пропсы — из `types.ts` рядом с компонентом) |
| `UiName+` | Компонента в дизайн-системе нет, нужен новый (раздел 9, там же обоснование и рекомендация) |
| `UiName~` | Компонент есть, но нужно небольшое расширение (раздел 9) |
| `Feature: Name` | Составной блок продукта. Собирается из компонентов дизайн-системы, но в саму систему не попадает: система «не знает о продукте» (`scaffold/README.md`, «Структура») |
| Мобильная / Десктоп | Мобильная — 390–430 px, один столбец. Десктоп — многоколонная раскладка |
| (assumption) | Моё предположение, ТЗ этого не говорит |

Иконки берутся только из реестра `IconName` (`icons/shapes.ts`): heart, search, pin, star, arrow-r, arrow-l, chev-d, chev-r, close, check, calendar, clock, share, bookmark, user, home, list, eye, lock, shield, crown, refresh, sparkle, filter, send, external, plane, settings, logout, trash, edit. Нужные, но отсутствующие иконки (`plus`, `bell`, `comment`, `more`, `flag`, `image`, `alert`, `wifi-off`, `chev-u`, `mail`) помечены `icon:+` и перечислены в разделе 9.

### 1.2. Каркас оболочки (задача 0004, здесь только точки стыка)

- **Корневые экраны** (Главная, Лента, Поиск, Профиль): верхняя панель оболочки (заголовок или логотип, город, Центр активности, вход в Поиск) и нижняя `UiTabBar` из пяти пунктов: Главная · Лента · Создать · Поиск · Профиль (§4.1). Пункту «Создать» нужна иконка `plus` (`icon:+`), ведёт не на страницу, а открывает панель C0.
- **Экраны второго уровня** (PO1, U1, K1, M2–M8, AC1, ST1, PR1, AI2 и др.): вместо шапки оболочки — `UiScreenBar+` (кнопка «Назад» `arrow-l`, заголовок, до двух иконок действий справа). Нижняя панель на них остаётся, кроме полноэкранных редакторов, диалога ИИ и авторизации (там нужна клавиатура и сосредоточение).
- **Десктоп:** шапка `UiAppHeader` (Главная · Лента · Поиск · Афиша · Подборки, город, действия справа в слоте `actions`) вместо нижней панели; выбор варианта — за оболочкой (0004). Старую структуру «Каталог/Избранное» не возвращаем (§25А.2).
- **Подвал** — `UiFooter` на длинных страницах (десктоп), на мобильном в конце корневых экранов, как в `home-mobile.png`; решает оболочка.

### 1.3. Сетка, отступы, типографика

- Мобильная: боковые поля `--s-4` (16 px), вертикальный шаг между блоками `--s-6`, между связанными элементами `--s-3`; внутри карточек `--s-4`. Всё — `UiStack` (`gap`), `UiCluster`, `UiGrid` (`min` — минимальная ширина колонки; на узком экране остаётся одна).
- Десктоп: основная колонка + боковая. Раскладка страницы — CSS-сетка на уровне страницы (`grid-template-columns`, доли `2fr 1fr`), либо `UiSplit+` (раздел 9). Ширину контейнера решает оболочка; в токенах её нет, поэтому здесь считаем долями, а не пикселями.
- Заголовок страницы — `UiText variant="h1"`, раздела — `h2`, карточки — `h3`, обычный текст — `body`, подписи — `caption`, надстрочные метки — `overline`, акцентное слово в заголовке — `UiAccentText`.
- Поверхности: карточки — `UiSurface variant="card"`, панели с отступом — `variant="panel"`. Вложенное — `--surface-2`.
- Акцент — лайм (`--lime`, `--accent-fg`) как метка, а не сплошная заливка экрана (§25А.1). Премиум не золотой, ИИ не фиолетово-синий: для обоих — лайм, иконки `crown` и `sparkle` (§25А.1). `--star` — только у оценок.

### 1.4. Базовые шаблоны, на которые ссылаются экраны

| Шаблон | Состав |
|---|---|
| **ScreenBar** | `UiScreenBar+`: `UiIconButton icon="arrow-l" variant="plain" label="Назад"`, `UiText h3`, справа `UiIconButton` (share, `more`) |
| **Строка раздела** | `UiCluster justify="between"`: `UiText h2` + `UiLink variant="accent" iconRight="arrow-r"` «Смотреть все» (как в `home-mobile.png`) |
| **Карточка заведения (вертикальная)** | `UiMediaCard` (`showFavorite`, слоты `badges` и по умолчанию: кухня, район, цена, `UiRating variant="summary"`) |
| **Карточка заведения (строка)** | `UiMediaCard~` с режимом `layout="row"`: фото слева, текст справа. Нужна в K1, AI2, M3, M7 |
| **Feature: PostCard** | `UiSurface card` + `UiAvatar+` + `UiText` + `UiImage` + строка контекста + панель действий. Три варианта: пользовательская, официальная заведения, подборка (см. F1) |
| **Пустое / ошибка** | `UiEmptyState+` и `UiBanner+` (раздел 8) |
| **Загрузка** | `UiSkeleton+` по форме страницы (раздел 8) |
| **Оверлей** | `UiSheet+`: шторка снизу на мобильном, диалог по центру или поповер у кнопки на десктопе (раздел 7) |

### 1.5. Состояния экранов (сводно, по §26.1)

Каждый значимый экран проходит: `initial_loading` → `loaded`; `empty`; `partial`; `refreshing`; `stale`; `offline_cached`; `recoverable_error`; `blocking_error`. Правила и тексты — в разделе 8. В каждом экране ниже указано только то, что для него особенное. «Пусто» и «ошибка» разводятся всегда: «Меню пока не опубликовано» не то же, что «Не удалось загрузить меню» (§26.1).

### 1.6. Движение: как выбирать (общее)

Каталог анимаций — `/motion` в `scaffold`; правило «сначала дешёвое» (`scaffold/README.md`, «Анимации»; заметки владельца о плавности на телефонах). Порядок: CSS transition и `:active` → Vue `<Transition>` и `<TransitionGroup>` → нативный `<dialog>` → WAAPI и View Transitions → `motion-v` только для пружин, жестов и раскладки, через `LazyMotion`.

| Тип перехода | Когда | Из каталога |
|---|---|---|
| **Сдвиг** (`--ease-drawer`, 350 мс) | Углубление: F1 → PO1, PO1 → U1, U1 → K1, список «Мое» → элемент | «Переход между страницами: Сдвиг» |
| **Затухание** (`--ease-out`, 120 + 220 мс, out-in) | Равные экраны: корневые вкладки, «Профиль ↔ Мое», содержимое вкладок | «Переход между страницами: Затухание» |
| **Шторка** (`--ease-drawer`, `--dur-drawer`) | Отдельная задача поверх экрана: O1–O11, редакторы CR1–CR4 на мобильном, авторизация, панель «Создать» | «Шторка» |
| **Окно по центру** (`--ease-out`, `--dur-modal`) | Диалоги на десктопе, подтверждения | «Модальное окно» |
| **Выпадающее** (`--ease-out`, `--dur-dropdown`, из места кнопки) | O1 и O10 на десктопе | «Выпадающий список» |

Сквозные решения (не повторяются в каждом экране):
- Нажатие: `:active` на всех кнопках («Нажатие», `--dur-press`).
- Сердце «подпрыгивает» только при включении («Переключатели и выбор»). Закладка, галочка, чип, переключатель — только цвет и положение за `--dur-hover`/`--dur-dropdown`.
- Индикатор вкладок `UiTabs`/`UiSegmented` — «Индикатор вкладок».
- Тосты — «Уведомления» (`--dur-toast`).
- Числа (лайки, комментарии, число подписчиков, цены, оценки) не «набегают»: значение меняется на месте («Без анимации»).
- Длинные ленты и списки (F1, AC1, M2–M8, комментарии) — без каскада: он только для редких коротких показов («Каскадное появление», пометка внутри демо).
- Общий элемент между экранами (`layoutId`) в мок не берём: тяжёлый (`motion-v`) и выгоды в этих путях нет (assumption).
- При `prefers-reduced-motion` смещения и масштаб уходят (`--motion-distance`), остаются прозрачность и цвет. Шторка проявляется, а не едет.
- Новых кривых, длительностей и keyframes не вводим. Скелетон без «мерцания»: пульсация потребовала бы нового keyframes, которого нет в каталоге (assumption; вопрос 21).

### 1.7. Качество на телефонах (из чек-листа владельца)

- Длинные списки (F1, AC1, M2–M8, комментарии, K1): `content-visibility: auto` у карточек вне экрана, страница монтирует блоки по одному в простое (`useProgressiveMount`), изображения `loading="lazy"` (уже так в `UiImage`).
- Не вешать `transform` на предка, внутри которого есть `position: fixed` или sticky (панели, шторки, закреплённые вкладки): переход страниц уже устроен так, шапка вне перехода.
- `backdrop-filter` только на устройствах с мышью; закреплённые панели на тач-экранах непрозрачные (`--surface`/`--bg`).
- Шторки — нативный `<dialog>` + `useAnimatedDialog`; библиотека `motion-v` — только для жеста смахивания и, возможно, перестановки в CR2, всегда лениво.
- Замер: собранная версия (`bun run build && bun preview`), процессор ×4 (как в README).

## 2. Лента и социальные экраны

### 2.1. F1 · Лента

**Маршрут:** `/feed` (assumption: маршрут в ТЗ не назван; принят владельцем). **Доступ:** гость видит, действия — через O5. **Источник:** §4.3, §12.1–12.4, §14.1, §26.3.
**Назначение:** поток публикаций, официального контента заведений и подборок; два уровня переключения: **Для вас | Подписки** и **Все | Авторы | Заведения**.

#### Мобильная

```
┌ шапка оболочки (город · Центр активности · Поиск) ┐
│ UiTabs:  Для вас │ Подписки                        │  закреплена
│ UiSegmented: Все │ Авторы │ Заведения              │  закреплена
│ [ Есть новые публикации ]  ← UiButton sm primary   │  только при новых
│ ┌ Feature: PostCard (пользователь) ───────────────┐│
│ │ UiAvatar+ Имя · @user · 2 ч        [more icon:+]││
│ │ UiImage 4/3 (или несколько, 1/N)                ││
│ │ Текст (3 строки, «ещё»)                         ││
│ │ [pin] Birch · Петроградский · ★4.7  → V1        ││
│ │ ♡ 24   💬 6   🔖   ↗                            ││
│ └─────────────────────────────────────────────────┘│
│ ┌ PostCard (официальный контент заведения) ───────┐│
│ ┌ PostCard (подборка) ────────────────────────────┐│
│ Рекомендательный блок (редко, в потоке)            │
│ UiTabBar                                           │
└────────────────────────────────────────────────────┘
```

Сверху вниз:
1. **Вкладки первого уровня** — `UiTabs` «Для вас | Подписки», закреплены под шапкой. `label="Лента"`.
2. **Источник** — `UiSegmented` «Все | Авторы | Заведения» (радиогруппа: выбор взаимоисключающий, три короткие подписи помещаются в 390 px). Чипы `UiChip` не подходят: это переключатели без взаимного исключения.
3. **Индикатор «Есть новые публикации»** — `UiButton size="sm" variant="primary" iconLeft="refresh"`, по центру под фильтрами. Новые записи внезапно не вставляются (§12.2); нажатие поднимает к началу и подгружает.
4. **Карточки** — `Feature: PostCard`, три варианта (§12.1: пользовательский и официальный контент должны визуально различаться):
   - **Публикация пользователя.** `UiSurface card`. Шапка: `UiAvatar+` круглый, имя (`UiText body`, полужирный), `@username` и время (`caption`, `--text-3`), справа `UiIconButton icon:+ more` (открывает O10). Медиа: `UiImage ratio="4/3"` (одно фото) или горизонтальная лента с `scroll-snap` и меткой «1/N» (`UiBadge variant="neutral"`). Текст: `UiText body`, усечение с «ещё». Контекст: строка `pin` + название заведения + район + `UiRating variant="summary"` (→ V1); при наличии — `UiChip size="sm"` с блюдом (→ V3) и с событием (`icon="calendar"`, → E2). Панель действий: `UiIconButton icon="heart" pressed` + число, `comment icon:+` + число (открывает O8), `bookmark pressed` (сохранить), `share` (O7).
   - **Официальный контент заведения.** Отличается тремя признаками сразу: (а) вместо круглого аватара — скруглённый квадрат `--r-md` с логотипом или фото заведения, а рядом название заведения; (б) `UiBadge variant="accent" pill icon="shield"` «Заведение»; (в) рамка `UiSurface` в цвете `--lime-line`. Кнопок комментариев нет (комментарии к официальному контенту — не в первой версии, §14.1); отметка «нравится» и сохранение описаны для публикаций, подборок и событий (§14.1–14.2, §18), поэтому для официального контента их не рисуем (assumption). Действия: `UiButton size="sm" variant="outline"` «Открыть заведение» (→ V1) и `UiIconButton share` (assumption).
   - **Подборка.** `UiTile` (5/4, фото, название, «N мест»), под ним автор (`UiAvatar+` + имя) или подпись «Редакция «Местами вкусно»» (`UiBadge variant="accent" pill`, §17.2). Действия: `bookmark` (сохранить как ссылку, §17.3), `share`. Тап — K1.
   - **Рекомендательный блок** (§12.1 «ограниченные рекомендательные блоки»): горизонтальная лента `UiTile` или `UiMediaCard` с заголовком-строкой раздела, не чаще одного на N карточек (assumption: N задаёт продукт). Внутри — только то, что уже разрешено рекомендательными модулями Главной (авторы, подборки, заведения).
5. **Конец ленты** — «Вы посмотрели всё новое» (`UiText caption`) и `UiButton variant="neutral" block` «Обновить» (assumption). Бесконечная подгрузка по курсору, без `UiPagination`.

#### Десктоп

- Две колонки, `2fr 1fr`: слева поток карточек в «читаемой» ширине (тот же `PostCard`, фото крупнее), справа закреплённая боковая колонка: `UiSegmented` «Все / Авторы / Заведения» (переезжает из потока), блок «Кого читать» (3–5 `UiAvatar+` + имя + `UiButton sm` «Подписаться»), «Подборки для вас» (2 × `UiTile`). `UiTabs` «Для вас | Подписки» остаётся над потоком.
- Действия в карточке те же, меню O10 — поповер у кнопки, комментарии — O8 как правая шторка или раскрытие под карточкой (assumption; на PO1 они в колонке).

#### Состояния

| Состояние | Что показываем |
|---|---|
| Загрузка | 3 × `UiSkeleton+` формы PostCard (аватар, строка, блок 4/3, две строки) |
| Пусто, «Подписки» без подписок | `UiEmptyState+`: «Вы пока ни на кого не подписаны», текст «Подпишитесь на авторов и заведения, чтобы видеть их публикации здесь», `UiButton` «Найти авторов» (→ Главная, модуль «Авторы»; assumption), под ним лента рекомендованных авторов |
| Пусто, «Подписки», есть подписки, нет новых | «Пока нет новых публикаций от тех, на кого вы подписаны» + переключение на «Для вас» |
| Пусто, фильтр «Заведения» без официального контента | «Заведения из вашего города пока ничего не публиковали» (assumption: текст) |
| Ошибка | Данные выше остаются; `UiBanner+ variant="warning"` «Не удалось обновить ленту» + `UiButton size="sm"` «Повторить». Блокирующая — на первичной загрузке без кэша: экран X2 (раздел 8) |
| Нет сети | Кэшированные карточки + `UiBanner+` «Нет сети. Показаны сохранённые публикации»; действия, требующие сети, отключены (`disabled`) |
| Без прав | Гость на «Подписки»: `UiEmptyState+` «Войдите, чтобы видеть публикации тех, на кого вы подписаны», `UiButton` «Войти» → O5 |
| Восстановление | «Назад» из PO1, U1, V1 возвращает режим, фильтр, курсор, просмотренные и прокрутку (§12.2, §26.3) |

#### Гость и авторизованный
- Гость: читает «Для вас» (общие сигналы, без личных: assumption). Отметка «нравится», комментарий, сохранение, подписка, «Не интересно» и др. → O5 (§5.1); действие откладывается и завершается после входа (§5.2).
- Авторизованный: полный набор; в меню O10 — негативные сигналы (§12.4). Свой пост в потоке помечается «Вы», меню — редактирование и удаление.

#### Переходы
Тап по карточке или тексту → PO1 (`/post/:id`), по автору → U1, по заведению → V1, по блюду → V3, по событию → E2, по подборке → K1, «комментарий» → O8, `share` → O7, `more` → O10, «Подписаться» (у рекомендованного автора) → O5 у гостя.

#### Анимации

Отменить» («Уведомления»); шторка для O8/O10/O7.

### 2.2. PO1 · Публикация

**Маршрут:** `/post/:id`. **Доступ:** гость видит, действия — O5. **Источник:** §13.1, §13.3, §13.4, §14.1–14.2, §15.2, §16.3, §21, §22.
**Назначение:** одна публикация с контекстом и комментариями; страница открывается по прямой ссылке без предварительного состояния (§22А).

#### Мобильная
1. **ScreenBar** — «Назад», заголовок «Публикация», `share` (O7), `more` (O10; у своей публикации — своё меню, см. ниже).
2. **Автор** — `UiAvatar+` + имя + `@username` + время + `UiButton size="sm"` «Подписаться» (у своей публикации кнопки нет). Тап по автору → U1 (закрытый профиль автора открывается как закрытый, §15.2).

4. **Текст** — `UiText variant="body-lg"`, полностью.
5. **Контекст** (структурные связи, а не упоминания, §14.3):

У гостя вместо поля — `UiButton variant="outline" block` «Войти, чтобы комментировать» → O5. Если автор отключил комментарии — `UiText caption` «Автор отключил комментарии», поле скрыто.

Автору над контентом показывается статус (`UiBadge`): «Черновик» (neutral), «На модерации» (warning), «Опубликовано» (success), «Запрошены изменения» (warning) + `UiBanner+` с причиной и кнопкой «Исправить» → CR1, «Отклонено» (danger, `UiBadge~`) + причина + «Подать апелляцию» (результат и статус видны пользователю, §21.4; сама форма апелляции в ТЗ пользователя не описана, вопрос 5). Меню автора в `more`: «Редактировать» (CR1), «Комментарии: вкл/выкл», «Сделать приватной» (публичная → приватная убирает публикацию из публичных мест сразу, §13.4; предупреждение в O12), «Удалить» (O12). - Все подразделы: `ScreenBar` («Назад», название раздела, справа `UiIconButton` действия), под ним `UiText caption` с `lock` «Видно только вам» там, где данные приватны.

- Бесплатных лимитов на количество нет (§18): счётчики без «из N», без намёков на Премиум.
- Удаление из списка: снятие сердца/закладки — сразу, элемент уходит («Добавление и удаление в списке») и появляется тост «Убрано. Отменить» (`UiToast+`).
- Длинные списки: подгрузка порциями по кнопке `UiButton variant="neutral" block` «Показать ещё» (assumption; пагинация `UiPagination` — для каталога, не для личных списков).

### 3.9. ST1 · Настройки

**Маршрут:** `/settings`. **Доступ:** авторизованный (гость видит только «Внешний вид» и документы, вопрос 4). **Источник:** §20.1–20.4, §20А, §19.3, §5.6, §5.7, §23.3, §24.3, §26.5.
**Назначение:** приватность, уведомления, аккаунт, запросы по персональным данным. «Не 40 переключателей» (§19.3).

#### Мобильная (один экран, пять групп)
Каждая группа: `UiText h3` заголовок + `UiSurface card` со строками `UiListRow+` (заголовок, пояснение `caption`, справа `UiSwitch`, `UiSegmented`, значение или `chev-r`).

```
ScreenBar: Назад · Настройки
── Приватность ─────────────────────────
Видимость профиля          [Публичный|Закрытый]
Видимость публикаций       [Публичная|Только для меня]
Персональные рекомендации  ( ● )
Разрешения ИИ              ›  (две строки-переключателя)
Заблокированные            0  ›
Скрытые авторы и заведения 3  ›
История                       ›
── Уведомления ─────────────────────────
Социальные                 ( ● )
Обновления заведений       ( ● )
События                    ( ● )
Рекомендации и маркетинг   ( ○ )
Системные                  🔒 всегда
── Аккаунт ─────────────────────────────
Email  maria@example.ru    Изменить
Профиль                    ›
Премиум                    Не подключён ›
Выйти
Запрос на удаление аккаунта  (текст --danger)
── Персональные данные ─────────────────
Запрос по персональным данным ›
Документы                     ›
── Внешний вид (assumption) ────────────
Тема                       UiThemeSwitch
```

1. **Видимость профиля** — `UiSegmented` «Публичный | Закрытый» + `caption`: у закрытого — «Ваша страница скрыта. Отдельные публичные публикации остаются в ленте и по ссылкам» (§15.2). Видимость публикации независима (§5.6).
2. **Видимость публикаций по умолчанию** — `UiSegmented` «Публичная | Только для меня» (значение для новых записей; в CR1 оно предзаполняется и всегда видно). Видимость подборок задаётся у каждой подборки (§20.1), поэтому здесь только пояснение `caption`.
3. **Персонализация** — `UiSwitch` «Персональные рекомендации». Под ним `caption`: «Если выключить, Главная и Поиск продолжат работать: подборки редакции, популярное и контекст города» (§20.3). Кнопка-ссылка «Сбросить профиль вкусов» (→ O12: «Сброс не удаляет ваши избранное, отзывы и записи», §20.3).
4. **Разрешения ИИ** — строка-заголовок с `caption` «Работают только с Премиум» (assumption; настройки доступны и без него, §20А) и два `UiSwitch`: «Доступ ИИ к личной библиотеке» (Избранное, Посещения, Оценки, приватные подборки, сохранённые события) и «Доступ ИИ к приватным текстам» (текст приватных публикаций и Дневника; выключено по умолчанию, §23.3). Два разных переключателя, не один. Пояснение: «Приватные данные других пользователей ИИ не использует». Значение по умолчанию первого — вопрос 17. Строка «Сервис не предназначен для учёта медицинских данных» (§23А) — `caption` под переключателями.
5. **Заблокированные / скрытые / история** — `UiListRow+` с `chev-r`, открывают вложенные экраны (маршруты `(assumption: /settings/blocked, /settings/hidden, /settings/history)`, вопрос 20): «Заблокированные» — список `UiAvatar+` + имя + `UiButton size="sm" variant="outline"` «Разблокировать» (подсказка: подписка не восстановится, §12.4); «Скрытые» — `UiTabs` «Авторы | Заведения» + строка + «Показывать снова»; «История» — действия «Очистить историю просмотров», «Очистить историю поиска», «Удалить историю диалогов с ИИ» (assumption: перечень, ТЗ называет только «управление историей»); каждое — O12.
6. **Уведомления** — пять `UiSwitch` (§19.3): Социальные, Обновления заведений, События, Рекомендации и маркетинг, Системные. Последняя строка без переключателя: `UiIcon lock` + «Безопасность и платежи приходят всегда» (обязательные сообщения не отключаются маркетинговым переключателем, §19.3). «Рекомендации и маркетинг» — точка отзыва согласия на рекламу (§20А): выключение отзывает маркетинговое согласие, текст-пояснение обязателен. Каналы (§19.2) отдельными переключателями не показываем, чтобы не дублировать все три без причины; для уведомлений на устройство — одна строка «Уведомления на устройстве» с системным разрешением браузера, запрашиваемым только по нажатию (assumption; вопрос 23).
7. **Аккаунт** — Email: значение + `UiButton variant="ghost" size="sm"` «Изменить» → шторка: `UiField` «Новый email» → `UiCodeInput` кода на **новый** адрес → подтверждение (§5.7), пока не подтверждено, старый работает, бейдж `UiBadge warning` «Ожидает подтверждения». «Профиль» → форма из A3 (имя, `@username` с ограничением на частую смену, аватар, «О себе», видимость). «Премиум» → PR1 (значение: «Не подключён» / «Активен до {дата}»). «Выйти» → сразу, без подтверждения (assumption). **Запрос на удаление аккаунта** — строка с `--danger` внизу группы → O12-диалог: что удалится, `UiText caption` про необязательный льготный период (§5.7, значение периода — вопрос 12), если активен Премиум — `UiBanner+ warning` «У вас активна подписка. Проверьте условия отмены автопродления» + ссылка в PR1 (§5.7 «проверка активного Премиум»; порядок и последствия ТЗ не описывает). Подтверждение: `UiCheckbox` «Я понимаю, что…» и `UiButton variant="primary"` «Отправить запрос»; для необратимого шага допустимо «Удержание для подтверждения» (assumption; редкое действие). Результат: статус запроса в самой строке («Запрос отправлен {дата}. Отменить?», §5.7).
8. **Персональные данные** — «Запрос по персональным данным» → шторка/страница: `UiSelect` тип запроса (assumption: Получить сведения, Исправить данные, Прекратить распространение публичных данных, Отозвать согласие, Другое; ТЗ называет прекращение распространения, отзыв согласия и общий запрос по данным, §20А), `UiTextarea+` описание, `UiButton` «Отправить», после — статус. Над формой явное разграничение: «Это не удаление аккаунта» и в диалоге удаления — обратная отсылка (§20А: два разных сценария). Ссылка «Удалить мой контент» → M4/M5/мои публикации (§20А). «Документы» → X3.
9. **Внешний вид** (assumption; вопрос 4) — `UiThemeSwitch` (`label`, `darkLabel`, `lightLabel` — русские подписи «Тёмная/Светлая»).

#### Десктоп
Master–detail: `UiSideMenu` слева (Приватность, Уведомления, Аккаунт, Персональные данные, Внешний вид; `secondaryItems`: «Выйти»), справа выбранная группа теми же строками `UiListRow+`. Якорь в адресе (`/settings#privacy`, assumption). Вложенные списки открываются как `UiSheet+` по центру.

#### Состояния
| Состояние | Что показываем |
|---|---|
| Загрузка | Скелет строк по группам |
| Сохранение | Переключатель применяется сразу (оптимистично), тост «Сохранено»; при ошибке возвращается и `UiBanner+ danger` «Не удалось сохранить» |
| Нет сети | Переключатели `disabled` + баннер «Нет сети. Настройки изменятся, когда связь вернётся» |
| Гость | Только группы «Внешний вид» и «Документы» + `UiEmptyState+`-карточка «Войдите, чтобы управлять приватностью» |
| Ошибка смены email | `UiField error`: «Такой адрес уже используется» / «Код неверен или устарел» |

**Переходы:** PR1, X3, A3-форма, M-разделы, O12, вложенные экраны настроек, `/activity`.
**Анимации:** да — переключатели (`--dur-dropdown`), шторки, «Раскрывающийся блок» не нужен (группы плоские); нет — анимация значений, выпадения групп; для смены темы — штатная (`useTheme`, затухание на тач-экранах).

## 4. Премиум и ИИ

### 4.1. PR1 · Премиум

**Маршрут:** `/premium`. **Доступ:** страница открыта всем; покупка — авторизованному 18+. **Источник:** §24.1–24.3, §25, §25Б, §5.8, §23.1–23.2, §23.8, §0А.
**Назначение:** что даёт Премиум, условия, покупка, состояние подписки, отмена автопродления, история платежей. Цены, периоды и пробный период не утверждены (§24.3): в моке заглушки без цифр, ничего не зашивается как окончательное.

#### Внешний вид (§25А.1)
Ни золота, ни фиолетово-синего градиента: акцент — лайм, значки `crown` и `sparkle`, «остров» `UiPromoPanel` (всегда тёмный, с лаймовым контуром и `UiSparks`, в том числе в светлой теме). Слово «Free» и «тариф» не используем.

#### Мобильная (состояние «нет подписки»)
```
ScreenBar: Назад · Премиум
UiPromoPanel  [Премиум]  ← badge
  «ИИ, который знает ваш город»   (assumption: заголовок)
  описание 2 строки
  UiButton primary block «Оформить Премиум»   ← ведёт к блоку покупки ниже
  note (lock): «Покупка доступна с 18 лет»
Что входит (UiInfoList, 8 пунктов)
Период подписки  UiSegmented: [Период A | Период B | Период C]  ← заглушки
Панель покупки  UiSurface panel
   Выбрано: {период — заглушка} · Цена: {будет указана}
   UiCheckbox «Мне исполнилось 18 лет»
   Автопродление: как отключить (UiText caption)
   UiButton primary block «Перейти к оплате»  (disabled, пока не отмечено 18+)
   UiText caption lock: «Оплата на стороне платёжного провайдера, реквизиты карты мы не храним»
   UiLink «Оферта Премиум»  → X3
Что не меняется  (UiInfoList: «Бесплатная версия остаётся полной», «Премиум не влияет на выдачу и охват»)
```
1. **Герой** — `UiPromoPanel` (`title`, `badge="Премиум"`, `description`, `note`), в слоте — `UiButton`. Note-пояснение с замком: «ИИ доступен только в Премиум» (как в референсах).
2. **Что входит** — `UiInfoList` (иконка, заголовок, пояснение). Пункты — сценарии первой версии (§23.2): «Поиск на естественном языке» (`search`), «Помощник по заведению» (`sparkle`), «Помощник по меню и блюду» (`list`), «Помощник по событиям» (`calendar`), «Сравнение 2–4 заведений» (`filter`), «Сводки публичных отзывов» (`star`), «Вопросы по вашей библиотеке — с вашего разрешения» (`lock`), «История диалогов» (`clock`). Не обещаем «умные подборки», «анализ дневника», «маршруты» (после первой версии, §23.2).
3. **Период** — `UiSegmented` из N позиций-заглушек «Период A/B/C» (assumption: состав периодов не утверждён; модель 1/3/12 месяцев — гипотеза, §24.3). Цена — текст «Цена будет указана» (assumption; вопрос 16). Пробный период показывается только при включённой конфигурации (assumption: скрыт по умолчанию; вопрос 15).
4. **Панель покупки** — `UiSurface panel`: сводка выбора; `UiCheckbox` «Мне исполнилось 18 лет» (assumption: способ подтверждения не описан в ТЗ, сам запрет — §5.8; вопрос 13); `UiButton block` «Перейти к оплате». Если аккаунт помечен 14–17 лет — `UiButton disabled` и `UiBanner+ info` «Оформление доступно с 18 лет». Условия: как отключить автопродление одной кнопкой в этом же экране, без «спрятанных» шагов (§25 «без манипулятивных приемов»); ссылка на оферту (`materials/legal/b2c/premium-offer.md` → X3). Промокода в форме нет (вопрос 14).
5. **Границы** — `UiInfoList` из двух пунктов: «Бесплатная версия остаётся полной» (§24.1), «Премиум не даёт охвата, приоритета модерации и значка» (§24.2).

#### Состояния подписки (§25), один экран, разные панели
| Состояние | Что показываем вместо блока «покупка» |
|---|---|
| Неактивно | Как выше |
| Пробный период (если включён) | `UiBadge accent` «Пробный период до {дата}», строка об автопродлении и кнопка «Отключить автопродление» |
| Активно | `UiSurface panel`: `UiBadge success icon="check"` «Активно до {дата}», «Автопродление: включено/выключено», `UiButton variant="outline"` «Отключить автопродление» (→ O12: последствия, без уговоров), `UiButton` «Открыть ИИ» → `/ai`; блок «История платежей» — `UiListRow+`: дата, статус, сумма-заглушка, ссылка на чек (`external`); «Условия продления» — раскрывающийся текст |
| Льготный период / проблема с платежом | `UiBanner+ warning`: «Не удалось списать оплату. Доступ сохранён до {дата}» + `UiButton` «Обновить способ оплаты» (→ провайдер, PR2) |
| Отменено, действует до конца периода | `UiBadge warning` «Автопродление отключено. Доступ до {дата}» + `UiButton` «Возобновить» (assumption: путь возобновления не описан, ТЗ говорит только об отмене) |
| Истекло | «Срок Премиум истёк {дата}». Отдельно `caption`: «Старые диалоги с ИИ можно читать, новые запросы недоступны. Ваши данные и публикации сохранены» (§23.8, §25) + `UiButton` «Оформить снова» |

#### После оплаты (PR2, заглушка)
- «Перейти к оплате» → промежуточный экран «Переходим к оплате в {провайдер}» (`UiText`, `UiButton loading`) → возврат на `/premium?result=…` (assumption: параметр).
- Результат: `pending` — «Проверяем платёж…» (покупку подтверждает сервер, а не переадресация, §25), `success` — `UiBanner+ success` «Премиум подключён» и `UiButton primary` «Вернуться» к сценарию из `premium_intent` (§25; например, к диалогу или заведению), `failed` — `UiBanner+ danger` «Оплата не прошла» + «Повторить». Сбой провайдера остальной продукт не ломает (§26.4).
- Фискальный чек и снимок условий (§25Б) — ссылки в «Истории платежей».

#### Десктоп
Две колонки, `3fr 2fr`. Слева герой, «Что входит», границы; справа **закреплённая панель покупки** (`UiSurface panel`) либо статус подписки. Панель «Ваш тариф» из `user-cabinet.png` заменена карточкой «Премиум» (M1).

**Гость:** страница видна; «Перейти к оплате» → O5 с сохранением `premium_intent`/`return_url`, после входа возврат на PR1, оплата 18+.
**Переходы:** `/ai`, AI2, X3 (оферта), PR2, возврат по `premium_intent`.
**Анимации:** да — «Индикатор вкладок»/сегмента для периода, «Смена состояния кнопки» «Перейти к оплате → загрузка» (CSS/`loading` в `UiButton`), тосты; нет — вспышки, конфетти, бегущие декорации, «счётчик экономии»: декор `UiSparks` статичен (assumption; демонстративная анимация не нужна и на слабых телефонах дорога).

### 4.2. AI1 · ИИ (вход)

**Маршрут:** `/ai`. **Источник:** §23.1–23.3, §23.5, §23.8, §22, §25.
**Назначение:** старт запроса для Премиум; для остальных — только контекстное предложение подписки.

#### Мобильная, Премиум
1. **ScreenBar** — «Назад», «ИИ», `UiIconButton icon="settings"` (→ ST1, «Разрешения ИИ»).
2. **Поле запроса** — `UiSearchInput label="Запрос к ИИ" buttonIcon="send" buttonLabel="Отправить"`, placeholder-пример («Тихое место для свидания в центре до 6000 ₽»).
3. **Подсказки** — горизонтальная лента `UiChip` сценариев §23.2: «Подобрать место», «Сравнить заведения», «Что заказать», «Что рядом сегодня». Тап подставляет запрос.
4. **Доступ к данным** — `UiListRow+` «Что ИИ знает о вас» → `UiSheet+` «Данные для ответов» (O14: два `UiSwitch`, как в ST1; вопрос 17), в строке `caption` «Публичные данные сервиса. Библиотека: включена/выключена».
5. **История диалогов** — `UiText h2` «Диалоги» + `UiListRow+` (первая реплика, дата, `chev-r`) → AI2. Пусто: «Диалогов пока нет».

#### Мобильная, бесплатная версия и гость (§23.1)
`UiPromoPanel` во всю ширину — контекстное предложение (O6 в виде страницы): заголовок «ИИ для сложных вопросов о еде», `badge="Премиум"`, короткий список выгод (3 строки), `UiButton primary block` «Узнать о Премиум» → PR1 (с `premium_intent`), `note` с замком «ИИ доступен только в Премиум». **Нет** поля ввода, квоты, счётчиков «осталось N», примера ответа, тизера сводки (§23.1). В референсах поле запроса с замком под баннером; для бесплатной версии заменяем на кнопку (вопрос 18): неактивное поле «обещает» работающий ИИ, а тап-сюрприз похож на ловушку.
Ниже — обычный бесплатный контент: «Поиск» и «Подборки» как ссылки (assumption).

#### Премиум истёк (§23.8)
Список старых диалогов доступен на чтение; вместо поля запроса — `UiPromoPanel` «Чтобы задать новый вопрос, подключите Премиум».

#### Десктоп
Две колонки: слева `UiSideMenu` со списком диалогов (пункты `NavItem`: `label` — первая реплика; assumption: список диалогов подаётся как навигация; `secondaryItems`: «Настройки ИИ»), справа приветственный блок (поле запроса, подсказки, доступ к данным). Бесплатная версия — одна колонка с панелью предложения.

#### Состояния
Загрузка диалогов — скелет строк; пусто — «Диалогов пока нет»; ошибка — `UiBanner+` «Не удалось загрузить историю»; нет сети — история из кэша только для чтения (assumption), отправка отключена. Сбой ИИ не ломает остальные страницы (§26.4).

**Гость:** только предложение подписки; «Узнать о Премиум» → PR1.
**Анимации:** да — шторка «Данные для ответов», нажатие; нет — «печатающиеся» подсказки, бегущий плейсхолдер.

### 4.3. AI2 · Диалог с ИИ

**Маршрут:** `/ai/chat/:conversationId`. **Доступ:** Премиум. **Источник:** §23.3–23.8, §23А, §22, §22А, §17.4, §26.4.
**Назначение:** запрос → короткий вывод + карточки + причины + компромиссы + кнопки + подсказки. Не длинное эссе (§23.5). Публичной ссылки на диалог нет, поэтому кнопки «Поделиться» и `share` здесь нет (§22); результат превращается в подборку и публикуется уже как подборка. Диалоги не индексируются (§22А).

#### Мобильная (без нижней панели, есть клавиатура)
```
ScreenBar: ← · «Тихое место для сви…»  · more
─ сообщение пользователя (справа, UiSurface panel) ─
─ ответ ИИ (без пузыря, блоки) ────────────────────
  Короткий вывод (UiText body-lg)  2–3 предложения
  Карточки: лента [ Card ][ Card ][ Card ]  (☐ для сравнения)
     Card: UiMediaCard~ row/компакт
       Почему: ✓ причина 1 · ✓ причина 2
       Компромиссы: • «Нет данных о …» 
       [ В избранное ] [ Открыть ]
  Кнопки:  [ Сравнить (2–4) ]  [ В подборку ]
  Подсказки: (chip) Подешевле  (chip) Только с верандой  (chip) Рядом со мной
  caption: Факты из опубликованных данных сервиса, мнения — из публичных отзывов
Доступ: 🔒 Библиотека: вкл · Приватные тексты: выкл ›
[ UiSearchInput  send ]  ← закреплено у клавиатуры
```
1. **ScreenBar** — «Назад», название диалога (первая реплика), `more`: «Переименовать» (assumption), «Удалить диалог» (O12). Кнопки «Поделиться» нет.
2. **Реплика пользователя** — `UiSurface variant="panel"`, выровнена вправо, `UiText body`.
3. **Ответ ИИ** — `Feature: AiAnswer`, состав строго по §23.5:
   - **Короткий вывод** — `UiText variant="body-lg"`, 1–3 предложения. Если данных нет — «В опубликованных данных сервиса не указано» (§23.4), а не догадка.
   - **Карточки объектов** — 1–5 `UiMediaCard~ layout="row"` (заведение или блюдо) в горизонтальной ленте на мобильном и сетке на десктопе. В карточке: фото, название, кухня/район/цена, `UiRating summary`, `UiCheckbox` выбора для сравнения (в режиме «Сравнить»). Тап → V1/V3.
   - **Причины и компромиссы** — под каждой карточкой два коротких списка: «Почему подходит» (`UiIcon check` + `UiText caption`) и «Компромиссы» (`UiIcon alert:+` + `UiText caption`). Неизвестное показываем явно («Часы не указаны»), не молчим (§23.6).
   - **Кнопки действий** — `UiButton variant="neutral" size="sm"`: «Сравнить» (активна при 2–4 выбранных), «В подборку» (создаёт **черновик** приватной подборки → CR2; публикация только явным действием, §17.4), «В избранное» у карточки.
   - **Подсказки для уточнения** — `UiChip` (2–4), тап отправляет как реплику.
   - **Пояснение об источниках** — `UiText caption` + `UiIcon shield`: «Факты — из опубликованных данных сервиса, мнения — из публичных отзывов» (§23.4).
4. **Сравнение 2–4** (§23.6) — блок-таблица `Feature: CompareTable`: столбцы — заведения (шапка: фото, название, `UiRating`), строки — Цена, Меню, Местоположение, Часы, Оценка, События, Темы отзывов, Соответствие вашим предпочтениям (только при разрешённой библиотеке). Пустые ячейки — «Нет данных» (не прочерк без смысла). **Абсолютного победителя не объявляем:** без «лучший выбор», без короны, без выделения одного столбца лаймом. Мобильная: горизонтальная прокрутка с закреплённым первым столбцом (подписи критериев). Семантика — `<table>`. Ниже кнопки «Открыть» каждого.
5. **Два разрешения на данные** (§23.3) — строка «Доступ к данным» над полем ввода → `UiSheet+` (O14): два `UiSwitch`: «Личная библиотека» (Избранное, Посещения, Оценки, приватные подборки, сохранённые события) и «Приватные тексты» (тексты приватных публикаций и Дневника; выключено по умолчанию). Если запросу нужна библиотека, а доступ выключен, в ответе вместо догадки — `UiBanner+ info`: «Чтобы учесть ваше Избранное, разрешите доступ к личной библиотеке» + `UiButton size="sm"` «Разрешить» (включает только первое разрешение). Данные других пользователей приватно не используются никогда (§23.3).
6. **Ввод** — `UiSearchInput label="Сообщение" buttonIcon="send"`, закреплён внизу. Во время ответа — `disabled` + `loading`.
7. **Медицинские сведения** (§23А) — при первом использовании в `UiSheet+` доступа `caption`: «Сервис не предназначен для учёта медицинских данных. Не сохраняем их как признак для рекомендаций» (assumption: формулировка; ограничение — §23А).

#### Десктоп
Три зоны: слева история (`UiSideMenu`, как AI1), по центру диалог (читаемая ширина), карточки в `UiGrid min=240` (две колонки), сравнение — широкая таблица на всю ширину диалога. Кнопка «Доступ к данным» — `UiSheet+` по центру.

#### Состояния
| Состояние | Что показываем |
|---|---|
| Новый (пустой) диалог | Как AI1, Премиум: поле, подсказки, доступ к данным |
| Ожидание ответа | Реплика пользователя + `UiSkeleton+` на 3 строки и ряд карточек, `caption` «Ищем в опубликованных данных…» (assumption) |
| Ошибка ответа | В ленте под репликой `UiBanner+ warning` «Не удалось получить ответ» + `UiButton size="sm"` «Повторить». Предыдущие ответы и остальной продукт работают (§26.4) |

| Нет доступа | Бесплатный пользователь открывает URL диалога: контекстное предложение подписки без содержимого (§23.1); гость → O5, затем то же |

**Анимации:** да — появление нового ответа «Добавление и удаление в списке» (opacity + короткий сдвиг, `--ease-out`), шторка доступа, нажатие; для ленты карточек — прокрутка с `scroll-snap`, без JS; нет — «печатающийся» текст, каскад карточек, подсветка «победителя», анимированные фоны (запретить «стандартные фиолетово-синие градиенты ИИ», §25А.1).

## 5. Создание контента

Общее для редакторов:
- Входят через C0 (панель «Создать», `UiSheet+` снизу: две крупные строки «Публикация» `edit` и «Подборка» `list`; на десктопе поповер у кнопки), либо из объекта с предзаполненным контекстом (заведение, блюдо, событие, Посещение). Гость сначала проходит O5 (§5.1), действие откладывается (§5.2).
- Маршрутов у редакторов нет (принято владельцем: полноэкранные редакторы поверх текущей страницы). Кнопка «Назад» браузера закрывает редактор, а не уводит со страницы.
- Мобильная: полноэкранная шторка (шторка «поднимается», основа отступает — шаблон «Шторка»). Десктоп: CR1, CR2 — страница-редактор в две колонки, CR3, CR4 — диалог по центру.
- Автосохранение обязательно (§13.2, §26.2): подпись состояния под заголовком (`UiText caption` + `UiIcon check`/`refresh`): «Сохранено», «Сохраняем…», «Нет сети. Сохранено на устройстве». Закрытие без публикации не теряет данных, оно превращает работу в черновик (M5). Отдельного «Сохранить черновик» нет.
- Выбор связанных объектов (заведение, блюдо, событие, Посещение) — `UiSheet+` O13.

### 5.1. CR1 · Редактор публикации

**Источник:** §13.1–13.5, §13А, §13Б, §16.3, §26.2, §14.1, §5.6.

#### Мобильная
```
┌ ScreenBar: ✕ · Новая публикация · [Опубликовать] ┐
│ ✓ Сохранено                                       │
│ Видимость: [ Публичная | Только для меня ]  ← всегда заметна
│   caption: «Увидят все. Пройдёт проверку»
│ Заведение *  ┌ Birch · Петроградский      ✕ ┐   │
│ Текст        ┌ UiTextarea+ ─────────────┐ 0/…│
│ Фото         [▣][▣][+ Добавить]  UiMediaPicker+ │
│ Связать:  (Блюдо) (Событие) (Посещение) (Оценка)│
│ Комментарии   ( ● ) разрешить                   │
│ caption: Правила: без платных и спонсорских интеграций
└───────────────────────────────────────────────────┘
```
1. **ScreenBar** — `UiIconButton close` («Закрыть»), заголовок, справа `UiButton size="sm" variant="primary"` «Опубликовать» (для приватной: «Сохранить в дневник»). Отключена, пока не выполнены условия: публичная — есть заведение (§13.1), текст или фото (assumption: минимум содержания в ТЗ не задан, вопрос 24).
2. **Видимость** — `UiSegmented label="Видимость"` «Публичная | Только для меня», закреплена и не сворачивается («приватная или публичная видимость всегда заметна», §13.2). Предзаполнено из настройки по умолчанию (ST1). Пояснение `caption`: у публичной — «Увидят все, пройдёт проверку»; у приватной — «Попадёт в Дневник. В ленту и рекомендации не попадёт». Переключение публичная → приватная убирает уже опубликованную запись из публичных мест сразу, приватная → публичная проходит процесс (§13.4): при редактировании существующей записи показываем это в `UiBanner+ info`.
3. **Заведение** — `UiField label="Заведение" hint="Обязательно для публичной публикации"`: выбранное — `UiSurface panel` (миниатюра, название, район, `UiIconButton close` «Убрать»), пусто — `UiButton variant="outline" block iconLeft="pin"` «Выбрать заведение» → O13. Для приватной записи — «необязательно». Отсутствующее заведение публично создать нельзя: `caption` «Не нашли заведение? Публиковать можно о заведениях из каталога» (§13.5; предложение нового — после первой версии).
4. **Текст** — `UiField label="Текст"` + `UiTextarea+` + счётчик символов (`caption`, число лимита — настраиваемое, §13.2, вопрос 24).
5. **Фото** — `UiMediaPicker+`: сетка превью `UiImage 4/3` с `UiIconButton close`, плитка «Добавить фото» (`image icon:+`). На каждом файле: загрузка (прогресс), ошибка с кнопкой «Повторить» на этом файле (§26.2 «повтор для каждого файла»). Лимит — настраиваемый, показываем `caption` «До {N} фото» только когда лимит задан.
6. **Связи** — ряд `UiChip` «Блюдо», «Событие», «Посещение», «Оценка», каждое открывает O13 своего типа. Выбранное — `UiChip variant="tag" removable`. «Блюдо» и «Событие» доступны после выбора заведения (§13.1). «Посещение» — из своих (M3) либо «Добавить» → CR4 (§16.4); при публикации оно остаётся приватным. «Оценка» — показывает текущую активную оценку этого заведения `UiRating stars` (без выбора новой) и ссылку «Изменить» → CR3 (§13.3: ссылка на активную оценку).
7. **Комментарии** — `UiSwitch` «Разрешить комментарии» (§13.1).
8. **Правила** — `UiText caption` со ссылкой `UiLink` «Правила публикаций»: платные, бартерные и спонсорские интеграции запрещены без официального рекламного процесса (§13Б, текст — assumption).

#### Порядок «Опубликовать» (публичная)
1. Первая публичная публикация → A5 (один раз, §13А), затем возврат в редактор.
2. Отправка → `UiSheet+` результата: `UiEmptyState+`-стиль «Отправлено на проверку», текст «Пока идёт проверка, публикация видна только вам. Статус — в «Мое → Черновики»» (J7, §13.4), кнопки «К публикации» (PO1), «Создать ещё». Для приватной — тост «Сохранено в дневник» + переход в M4.

#### Десктоп
Страница-редактор в две колонки, `2fr 1fr`. Слева текст и фото. Справа закреплённая панель: видимость, заведение, связи, комментарии, кнопка «Опубликовать» и статус автосохранения. `UiBreadcrumbs` «Создать › Публикация» (assumption).

#### Входы с предзаполнением
С V1 — заведение и, при необходимости, блюдо; с E2 — заведение и событие; с M3 — заведение и Посещение. Предзаполненное поле помечено «Из карточки заведения» и редактируется.

#### Состояния
| Состояние | Что показываем |
|---|---|
| Новое | Пустые поля, видимость по умолчанию, «Опубликовать» отключена |
| Восстановление | Открытый черновик с полями и подписью «Восстановлено из черновика» |
| Загрузка файла | Прогресс на плитке; «Опубликовать» ждёт завершения |
| Ошибка файла | Плитка с `UiIcon alert:+` и «Повторить»; остальное не теряется |
| Ошибка отправки | `UiBanner+ danger` «Не удалось отправить. Черновик сохранён» + «Повторить» (идемпотентно, §26.2) |
| Нет сети | `UiBanner+` «Нет сети. Черновик сохранён на устройстве. Отправим, когда связь вернётся»; «Опубликовать» доступна только в очереди (assumption) |
| Ошибки полей | `UiField error`: «Выберите заведение», «Добавьте текст или фото» |
| Запрошены изменения | `UiBanner+ warning` с причиной модерации над полями |
| Без прав | Гость — O5 до открытия. Пользователь, которому запретили публикацию (санкции), — вне ТЗ, вопрос 26 |

**Переходы:** O13, CR3, CR4, A5, PO1, M4/M5, O12 (удалить черновик).
**Анимации:** да — шторка (вход снизу) и закрытие тем же путём; «Добавление и удаление в списке» для плиток фото; «Раскрывающийся блок» для `Связать` при выборе (assumption); прогресс загрузки без «красоты»; нет — анимация счётчика символов, «конфетти» после публикации.

### 5.2. CR2 · Редактор подборки

**Источник:** §17.1, §17.4, §20.1, §26.2. **Мок:** P1.

#### Мобильная
1. **ScreenBar** — `close`, «Новая подборка», справа `UiButton size="sm"` «Опубликовать» (публичная) или «Сохранить» (приватная); строка автосохранения.
2. **Название** — `UiField label="Название"` + `UiInput` (обязательно).
3. **Описание** — `UiTextarea+` (assumption: поле необязательно; вопрос 9).
4. **Видимость** — `UiSegmented` «Публичная | Только для меня» (для каждой подборки отдельно, §20.1). Публичная: `caption` «Увидят все». Приватная — не показывается никому и не индексируется.
5. **Заведения** — заголовок `UiText h2` «Заведения ({N})», кнопка `UiButton variant="outline" iconLeft="plus icon:+"` «Добавить заведение» → O13 (тип «заведение»). Список `UiSurface card`, элемент — `Feature: CollectionItemEditor`: миниатюра, название, кнопки «Выше»/«Ниже» (`UiIconButton chev-u:+`/`chev-d`, порядок авторский, §17.1) и `close` (убрать), под ними `UiTextarea+` «Заметка автора» (необязательно), `UiChip` «Блюдо» и «Событие» (необязательный контекст, §17.1). **Дублей нет:** при добавлении уже имеющегося заведения — не добавляем, существующая строка мигает акцентом (без анимации, только рамка `--lime-line` на 1 с) и `UiField error` «Это заведение уже в подборке».
6. **Подборка из ИИ** — если черновик создан из AI2 (§17.4): `UiBadge accent icon="sparkle"` «Создано ИИ» и `UiBanner+ info` «Проверьте и отредактируйте: публикация только по вашей кнопке».

#### Десктоп
Две колонки: слева `1fr` закреплённые поля (название, описание, видимость, «Опубликовать»), справа `2fr` список заведений с редактированием.

#### Состояния
Новая — пустой список и `UiEmptyState+` «Добавьте первое заведение»; восстановление — «Восстановлено из черновика»; «Опубликовать» отключена без названия и хотя бы одного заведения (assumption); ошибки сохранения/сети — как CR1; при публикации публичной — «Отправлено на проверку» (assumption: статус модерации у подборки указан в задаче M5; сам процесс в ТЗ для подборок не описан, вопрос 19).
**Анимации:** «Добавление и удаление в списке» (FLIP) для добавления, удаления, перестановки кнопками — сначала так («сначала дешёвое»); перетаскивание (`motion-v`, `layout` + `drag`, лениво) — только если продукту понадобится, как улучшение и с кнопочной альтернативой; нет — «взлёт» строки при добавлении.

### 5.3. CR3 · Оценка и отзыв

Кнопка `UiButton primary block`: «Сохранить оценку» (только звёзды) либо «Опубликовать отзыв» (есть текст/фото). `caption`: «Отзыв публичный и проходит проверку. Оценка — одна на заведение» (§16.1–16.2).

### 5.5. A5 · Юридическая настройка первой публичной публикации

**Источник:** §13А, §13Б. **Мок:** P1. **Тексты документов:** `materials/legal/b2c/*` (пользовательское соглашение, согласие на распространение ПД).
**Назначение:** отдельный экран один раз перед первой публикацией с `visibility=public`; не повторяется, пока версия и область согласия не изменились и согласие не отозвано.

#### Мобильная (полноэкранная шторка поверх CR1)
1. **ScreenBar** — «Назад к редактору», заголовок «Перед первой публикацией».
2. **Что произойдёт с публичной записью** — `UiInfoList` (§13А): «Лицензия ООО «ВСЕМ» на всю территорию мира» (`share`), «Использование внутри сервиса и во внешней рекламе и PR «Местами вкусно»» (`eye`), «Индексация поисковиками, если тип объекта это допускает» (`search`). Приватные записи получают только техническую лицензию и не индексируются (`caption`).
3. **Согласия — раздельные, ничего не отмечено заранее:**
   - `UiCheckbox` «Принимаю лицензию на публичный пользовательский контент» + `UiLink` на документ (`public_ugc_license_acceptance`, обязательно);
   - `UiCheckbox` «Согласен на использование моего изображения и голоса» (`image_voice_consent`, обязательно для публичной публикации: assumption);
   - `UiCheckbox` «Согласие на распространение персональных данных» (`distribution_consent`) — показывается только «если применяется» (§13А; условие показа — вопрос 25).
4. **Кнопки** — `UiButton primary block` «Принять и опубликовать» (отключена, пока не отмечены обязательные), `UiButton variant="outline" block` «Оставить приватной» (сохранить как «Только для меня», не тупик), `UiButton variant="ghost"` «Вернуться к редактору».
5. Документ открывается в новом окне или `UiSheet+`, черновик не теряется.

Сервер фиксирует документ, версию, дату и время, источник (§13А); в интерфейсе — `UiText caption` «Версия документа от {дата}».

#### Десктоп
Диалог по центру, те же блоки.

#### Состояния
Ошибка фиксации согласия — `UiBanner+ danger` + «Повторить», публикация не отправляется; сеть — как CR1; **обновилась версия документа** — тот же экран с `UiBanner+ info` «Документ обновлён. Подтвердите ещё раз» (assumption).
**Переходы:** обратно в CR1 с автоотправкой или возвратом к редактору; X3.
**Анимации:** шторка; нет — всё остальное.

## 6. Авторизационный поток на мобильном (A1–A4)

**Маршрут:** один поток `/auth` (assumption; принят владельцем), открывается поверх текущей страницы (O5) и по завершении возвращает на `return_url`. **Источник:** §5.1–5.8, §5.3А, §20.2. **Мок:** P0.
**Что не входит (по ТЗ и по задаче):** пароль (только код на email, §5.3), промокод (промокоды пользователя — отдельная сущность, §25), пробный период и «Премиум активирован» (пробный период — гипотеза, §24.3), вход через соцсети (на будущее, §5.3), обязательный телефон (§5.3), стена регистрации до получения ценности (§5.1).

### 6.0. Общее для A1–A4

- **Оболочка потока:** полноэкранная шторка (на мобильном) без нижней панели. Сверху `UiScreenBar+`: слева `UiLink variant="muted" iconLeft="arrow-l"` «Назад» (шаг назад; с A1 — «Закрыть», отмена возвращает на страницу, отложенное действие снимается (assumption)), по центру `UiLogo size="sm"`.

- **Контекст** (§5.2): под логотипом `UiCluster` с `UiIcon` и `UiText body`, что пользователь пытался сделать: «Чтобы добавить Birch в избранное, войдите» (по `action_type` и `object_id`). Если действия нет (вход из профиля) — строки нет.

- **Десктоп:** тот же поток в `UiSheet+` по центру. При открытии как отдельная страница (прямая ссылка `/auth`) — двухчастный макет референса: слева `UiImage ratio="fill"` с подписью «Ваш вкус начинается здесь» и тремя строками-выгодами (`UiInfoList`: `bookmark` «Сохраняйте места», `clock` «Ведите историю посещений», `star` «Находите новые заведения»), справа форма. - **Ошибки сети** — `UiBanner+ danger` сверху формы «Нет соединения. Попробуйте ещё раз», поля сохраняют значения.

2. `UiField label="Email" hint="name@example.ru"` + `UiInput type="email"` (`autocomplete="email"`).
3. Согласия — `UiStack gap=3`, каждое `UiCheckbox`, ничего не отмечено заранее:
   - «Мне есть 14 лет» (assumption: способ проверки возраста в ТЗ не описан; чекбокс — дефолт из `front-structure.md`, вопрос 6 там; аккаунт с 14 лет, §5.8);

### 6.2. A2 · Ввод кода

1. `UiText h1` «Введите код»; `UiText body`: «Код отправлен на» + адрес полужирным; `UiLink variant="accent"` «Изменить email» (возврат на A1 с заполненным адресом).
2. `UiField label="Код из письма"` + `UiCodeInput length=6` (assumption: длину кода ТЗ не называет, в референсе шесть ячеек; автофокус, вставка целиком, автоотправка при заполнении, `autocomplete="one-time-code"`).
3. **Повторная отправка** (§5.4, пауза настраиваемая): `UiText caption` «Отправить код повторно через 00:42» → по истечении `UiButton variant="outline" iconLeft="refresh"` «Отправить код повторно».

| Ситуация | Поведение |

## 7. Оверлеи O1–O11 и добавленные O12–O14

### 7.0. Единый способ сборки

Все оверлеи собираются из одного компонента `UiSheet+` (раздел 9) на нативном `<dialog>` и `useAnimatedDialog`: фокус, Escape, «инертный» фон, возврат фокуса на кнопку-источник — у браузера.

| Режим | Где | Форма | Движение |
|---|---|---|---|
| `bottom` | Мобильная | Шторка от нижнего края, `--r-xl` сверху, «ручка» сверху, максимум высоты 90% экрана, длинное содержимое прокручивается внутри, кнопки действий закреплены внизу | «Шторка»: `translateY`, `--ease-drawer`, `--dur-drawer`; смахивание вниз закрывает («Смахивание», `motion-v` лениво, всегда есть `close` и Escape) |
| `center` | Десктоп; диалоги подтверждения на любых экранах | Окно по центру, ширина по содержимому | «Модальное окно»: `opacity`, `scale 0.96 → 1`, `--ease-out`, `--dur-modal` |
| `anchor` | Десктоп: O1, O10, C0 | Поповер у кнопки-источника | «Выпадающий список»: `transform-origin` у триггера, `--dur-dropdown` |
| `full` | Мобильная: редакторы CR1–CR3, поток A1–A4 | Полноэкранная шторка со `ScreenBar` | «Шторка» |

Правила для всех:
- Заголовок обязателен (`aria-labelledby`), `UiIconButton close` в шапке (кроме `bottom`-шторок из списка действий, где закрывает тап по фону и «Отмена»).
- Затемнение фона — только цвет; `backdrop-filter` не используем (тач-устройства).
- При `prefers-reduced-motion` шторка не едет, а проявляется.
- Порядок наложения: подтверждение (O12) поверх любого другого.
- Все `UiButton` внизу: главная — `primary` `block`, отмена — `ghost` под ней; опасная — `primary` с `--danger` не вводим (в системе нет такого варианта: разрушительное действие — `UiButton variant="outline"` с текстом `--danger` и отдельным подтверждением, вопрос 28).

Тексты пишутся под конкретный экран (примеры в экранах выше); ниже — общие шаблоны сборки. Страница 404 (X1) уже есть в референсе и в них не разбирается.

### 12.1. Что не решается по ТЗ и оставлено дефолтом

- Точные тексты (заголовки, подписи, пояснения) — рабочие формулировки, финальные нужен контент-менеджер и юрист (особенно A1, A5, O3, PR1, удаление аккаунта).
- Перечень категорий жалоб, метрик автора, типов запроса по персональным данным, периодов подписки — придуманы как рабочие значения, ТЗ их не перечисляет.
- Проверка возраста 14+ и 18+ — способ не описан.
- Форма апелляции — только статус в Центре активности.
