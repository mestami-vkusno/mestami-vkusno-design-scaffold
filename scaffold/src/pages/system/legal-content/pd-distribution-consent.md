# Приложение 1. Рекомендуемая модель пользовательского интерфейса, если документ применяется (внутреннее примечание, не для публикации)

## Вариант А — настройка Профиля

Пользователь выбирает:

**Профиль**
- Приватный
- Публичный

При первом переходе в публичное состояние система:

1. показывает информацию о публичных полях;
2. предоставляет отдельную форму согласия;
3. позволяет определить перечень данных;
4. фиксирует запись согласия;
5. только после этого включает публичное состояние.

## Вариант Б — публикация пользовательского контента

При первой публичной публикации:

> Эта публикация будет доступна другим пользователям и может отображаться в вашем публичном профиле, карточке заведения, Ленте и Поиске.

Далее, если юридически требуется ст. 10.1:

- отдельное действие по согласию;
- выбор категории данных;
- фиксация версии и условий.

Повторные публикации могут использовать действующее согласие только в пределах явно охваченных им категорий и условий.

## Вариант В — приватность по умолчанию

Если Пользователь не предоставил применимое согласие на распространение:

- Профиль остается приватным;
- пользовательский контент по умолчанию приватный;
- Сервис не трактует отсутствие выбора как согласие.

# Приложение 2. Критический юридический вопрос перед запуском (внутреннее примечание, не для публикации)

Перед внедрением настоящего документа необходимо получить финальное заключение российского юриста по персональным данным на следующий вопрос:

> Требует ли выбранная модель самостоятельной публикации Пользователем псевдонимного Профиля и пользовательского контента в «Местами вкусно» отдельного согласия по ст. 10.1 Федерального закона № 152-ФЗ в каждом соответствующем сценарии либо может быть реализована на иной корректной правовой конструкции без обязательного сбора реального ФИО Пользователя?

Пока этот вопрос не решен:

- не добавлять ФИО в обязательную регистрацию;
- не менять псевдонимную модель Профиля;
- не считать настоящий документ обязательным для всех Пользователей;
- не включать его в промышленную эксплуатацию без проверки финального интерфейса.
