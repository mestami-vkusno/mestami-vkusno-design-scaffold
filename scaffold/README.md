# scaffold — Vue-разметка дизайн-системы «Местами вкусно»

Каркас фронтенда: дизайн-система из `../design-system.html`, разобранная на минимальные типизированные компоненты Vue 3 + TypeScript, и страница-витрина, которая их показывает. Документы в `materials/` рабочей области — источник истины по функциям; здесь только форма, цвет и состояния.

## Запуск

```sh
bun install
bun dev             # http://localhost:5173 — продукт; /design-system — витрина дизайн-системы, /motion — анимации
bun run build       # проверка типов (vue-tsc) и сборка
bun run type-check
```

## Компоненты для экранов продукта

Добавлены задачей 0016 (раздел 9 `docs/screens-without-reference.md`); все показаны на `/design-system` в разделах «Ввод», «Списки», «Состояния».

- **atoms:** `UiAvatar` (круг и скруглённый квадрат, инициалы-заглушка с `tone`), `UiTextarea` (авто-рост, счётчик по `maxLength`, работает внутри `UiField`), `UiRadio` и `UiRadioGroup` (нативные радио внутри `role="radiogroup"`, стрелки от браузера), `UiSkeleton` (`text`/`block`/`circle`, без пульсации; со слотом — контейнер `role="status" aria-busy`), `UiRatingInput` (1–5, `radiogroup`, звёзды).
- **molecules:** `UiListRow` (`href` → `<a>`, `@click` → `<button>`, `v-model:toggle` → строка-переключатель; справа значение, шеврон, галочка, слот), `UiBanner` (`info|success|warning|danger`, `dismissible`, действие в слоте), `UiToast` + `useToast()`, `UiEmptyState` (`empty|error|offline|guest`), `UiMediaPicker` (нативный `<input type="file">`, превью, прогресс, «Повторить», удаление; загрузку подставляет продукт через `uploader`, для мока — `simulateMediaUpload()`).
- **organisms:** `UiScreenBar` (назад, заголовок, до двух действий в слоте, safe-area).
- **иконки:** `comment`, `more`, `flag`, `image`, `alert`, `wifi-off`, `chev-u`, `mail`, а также `info` (нужна баннеру).
- **расширения:** `UiBadge` (`variant="danger"`, `dot` с `label`), `UiMediaCard` (`layout="row"`), `UiInput` (`type="date"`, `max`, `min`), `UiImage` (`ratio="1/1"`).

**Уведомления.** `<UiToast />` монтируется в оболочке один раз (регион `aria-live` должен быть на странице до первого сообщения; лишние экземпляры молчат), показывает их `useToast().show({ text, variant, action, duration })`. Регион живёт в верхнем слое (`popover`), поэтому виден и над открытой шторкой. Нижний отступ — токен `--toast-bottom` (по умолчанию 16 px + safe-area): над нижней навигацией оболочка задаёт его сама. Автозакрытие 4 с (с кнопкой 8 с) стоит на паузе, пока на тосте курсор или фокус; Escape закрывает тост, когда фокус внутри него. Тост не несёт собственного `role`: объявляет его регион `aria-live="polite"`, иначе `role="alert"` внутри региона озвучивался бы дважды.

## Состояние мока

Каталог `src/state/` — единственное место, где страницы берут сессию, библиотеку пользователя и Премиум. Без бэкенда и без Pinia: модульные синглтоны на `shallowRef`, данные — из `src/mocks/`.

**Правила использования.**
- **Откуда импортировать.** Оболочка и страницы берут `useViewer` и `useAuthGate` из `@/shell/composables/*` (лёгкие, живут в основном чанке); `useLibrary` и `usePremium` — из `@/state/useLibrary` и `@/state/usePremium` (тяжёлые, тянут данные моков; в основной чанк не входят, только вместе со страницей). Индекса у `state/` нет намеренно: общий импорт затянул бы тяжёлое в основной чанк.
- **Гость.** Любое значимое действие (Избранное, подписка, «нравится», сохранение, комментарий, Посещение, Оценка, Отзыв, создание, Премиум, ИИ; ТЗ §5.1) идёт через `requireAuth`. Методы `useLibrary` и `usePremium` делают это сами: гостю возвращают `{ ok: false, reason: 'auth_required' }`, сохраняют отложенное действие в `sessionStorage` (срок `PENDING_TTL_MS` = 30 минут, истёкшее игнорируется) и открывают `/auth`. После входа страница-получатель вызывает `consumePendingAction()` и исполняет действие: `applyPendingAction(action)` из `useLibrary` «включает» избранное, подписку, отметку, сохранение, ставит оценку и так далее (повтор не переключает обратно); затем переходит на `action.returnUrl`. Списки у гостя пусты.
- **Результат.** Действия не бросают исключений: `{ ok: true, … } | { ok: false, reason }`. Итог (успех или понятная причина) показывается тостом `useToast()` из дизайн-системы; результат возвращается и вызывающему, если ему нужна навигация.
- **Хранение.** `localStorage` под префиксом `mv-state:` с версией схемы; при недоступном хранилище (приватный режим) состояние живёт в памяти. `resetMock()` (из `@/shell/composables/useViewer` или `@/state/reset`) стирает всё и возвращает исходное: гость, `MOCK_LIBRARY`, Премиум как в `MOCK_USER`. Выбор города не затрагивается.
- **Данные.** Заведения, публикации, подборки, события — только селекторами `src/mocks/selectors/*`; `menusRaw` и алкогольные позиции состояние не читает. Селекторы `feed()`, `reviewsByVenue()`, `libraryOf()` считают по исходным данным и не видят изменений пользователя, поэтому там, где нужны изменения, берите чтения `useLibrary` (`feedItems`, `reviewsForVenue`, `commentThreads`, `visits`, `ratings` и т. д.). Личное (Избранное, Посещения, оценки, сохранения) в публичные выдачи не попадает.
- **Правила ТЗ в действиях.** Оценка: одна активная на пару «пользователь × заведение», новая заменяет прежнюю (та остаётся неактивной), отзыв переезжает на новую. Отзыв: один на пару, повторный вызов редактирует, нужна активная оценка. Посещение: повторные разрешены, дата не позже «сегодня» мока (`future_date`). Блокировка сильнее подписки: снимает её, разблокировка не возвращает, подписаться на заблокированного нельзя (§12.4).
- **Премиум.** Фазы `none | trial | active | grace | canceled_active | expired`; `canUseAi` истинно в `trial`, `active`, `grace`, `canceled_active`; старые диалоги ИИ читаются всегда у вошедшего (§23.8). `startPurchase({ ageConfirmed: true })` мгновенно делает «активно» и возвращает `returnUrl` из `premium_intent`, который контекстное предложение сохраняет через `rememberIntent()`. `setMockPhase()` — только для мока, чтобы показать любое состояние.

## Оболочка и маршруты

- **Адреса.** `/` — продукт (Главная), `/design-system` — витрина, `/motion` — анимации, `/features` — общие блоки продукта; неизвестный путь открывает 404 в оболочке продукта, а не ведёт на `/`. Ссылки на витрину и анимации — в служебной строке подвала.
- **Все маршруты заведены заранее** в `shell/data/routes.ts` (карта страниц — `docs/front-structure.md`, раздел 2). Задача над страницей заменяет содержимое её файла в `src/pages/<группа>/` и **не трогает `router.ts`**. Новая страница — новая строка в таблице и файл. Заглушка берёт название, ID и подсказку из таблицы; у заменённой страницы корневой элемент — `<main>`.
- **Две раскладки.** `meta.layout`: `product` (по умолчанию: шапка города и Центра активности, нижняя навигация на мобильном, верхняя на десктопе от 900 px, подвал) и `showcase` (прежняя шапка `SiteTopbar`). `meta.chrome: 'focused'` убирает подвал и нижнюю навигацию (вход, редакторы, диалог с ИИ).
- **Ссылки.** Компоненты дизайн-системы отдают обычный `<a href>`; `useInternalLinks` превращает клик по внутренней ссылке в переход роутера (внешние, `target="_blank"`, `#якоря` и Ctrl/⌘-клик не перехватываются). В страницах достаточно `UiButton href="/venue/1"`.
- **Корневые вкладки** (`keepAlive` в таблице: Главная, Лента, Поиск, Профиль) держатся в памяти `<KeepAlive>` (не больше их числа, без роста), их прокрутка запоминается; повторное нажатие на активную вкладку возвращает наверх. «Назад» и «Вперёд» возвращают сохранённое положение любой страницы (`shell/scroll.ts`). Страницы корневых вкладок не читают `useRoute()`: пока вкладка в фоне, он показывает чужой маршрут.
- **Панели без маршрута** — `UiSheet`: снизу шторкой на телефоне, окном по центру от 720 px. «Создать» (Публикация, Подборка) и выбор города открываются из шапки и нижней навигации через `useShellOverlays`.
- **Город** — `useCity`: Санкт-Петербург и Москва, выбор помнится в браузере, бэкенда нет. Сессия — `useViewer` (гость или тестовый пользователь), см. «Состояние мока».

## Общие блоки продукта (`features/`)

Составные блоки, которыми пользуются сразу несколько страниц (раздел 9.3 `docs/screens-without-reference.md`). Собраны из компонентов `@/design-system` и типов и заглушек фото из `@/mocks`; дизайн-система о них не знает. Все состояния показаны на служебной странице `/features` (ссылка в подвале рядом с `/design-system` и `/motion`, из продукта ссылок нет).

**Перечень.**
- **Заголовки и ряды:** `SectionHeader` («Смотреть все»), `HorizontalRail` (CSS scroll-snap, стрелки только при `(pointer: fine)`, стрелки/Home/End на клавиатуре, `role="group"` с подписью).
- **Заведения:** `VenueCard`, `VenueRow` (фото, кухня, район, чек, оценка, расстояние, NEW, «Сегодня событие», статус); `RatingLabel` (агрегат скрыт при малой выборке), `OpenNowLabel`, `PriceLabel` (чек, цена позиции, 6 видов цены события), `StatusBadge` (статусы заведения и события).
- **События и подборки:** `EventCard`, `EventRow`, `CollectionCard` (плитка и строка).
- **Люди и отзывы:** `PhotoAvatar`, `AuthorRow`, `AuthorCard`, `CommentItem` (один уровень ответов, состояния отправки), `ReviewCard`, `DishRow` (алкоголь не рисуется).
- **Действия:** `ActionButton` (основа), `ShareButton` (лёгкая), `FavoriteButton`, `FollowButton`, `LikeButton`, `SaveButton` (через `useLibrary`).
- **Поток и ИИ:** `PostCard` (`data.variant`: `user`, `venue`, `collection`; официальный отличается подписью «Заведение», скруглённым аватаром, рамкой `--lime-line`), `AiTeaser` (§23.1: предложение без поля с замком и без текста сводки; у активного Премиум — поле, ведущее на `/ai`), `CardSkeleton` (форма загрузки под каждый блок).
- **Оболочка:** `useDocumentTitle()` в `shell/composables` — заголовок вкладки по данным страницы («Birch · Местами вкусно»).

**Правила.**
- Один блок — одна папка `features/<Block>/<Block>.vue` и рядом `types.ts` с пропсами. Данные приходят только пропсами (типы из `@/mocks/types`), блок сам ничего не выбирает из данных; названия районов и заведений передаёт страница из селекторов. Тексты — в `features/labels.ts` и в пропсах, форматирование — из `@/mocks/format`.
- Слои: `features` импортируют `@/design-system`, `@/mocks` (типы, `format`, `dictionaries`, `UiPhotoPlaceholder`) и `@/state/*`; дизайн-система `features` не импортирует.
- Фото — `UiPhotoPlaceholder` (данные `{ ratio, tone, caption }`). Карточки — `<article>` с заголовком нужного уровня (`headingLevel`), вся карточка — одна цель нажатия (растянутая ссылка на названии, кнопки лежат выше), рамка фокуса на самой карточке. Длинные списки — `deferred` (`content-visibility: auto`, у строк и постов включён по умолчанию).
- Действия гостя идут через `requireAuth` на `/auth` с отложенным действием, у вошедшего переключаются сразу (состояние общее и синхронное) и показывают тост; состояние — `aria-pressed`. «Подпрыгивание» сердца — WAAPI при включении, при уменьшенном движении его нет. Наведение и стрелки рядов — только для мыши, `backdrop-filter` не используется.
- `ShareButton` не открывает шторку сам: он шлёт `window`-событие `mv:share` (`SHARE_EVENT`, `detail` — `ShareTarget`) и `emit('share')`. Шторка «Поделиться» (0013) забирает событие через `preventDefault()`; пока её нет, блок копирует ссылку и показывает тост.

**Ленивые импорты.** Общий индекс `@/features` — только лёгкие блоки (без `useLibrary` и `usePremium`), в основной чанк он не попадает: блоки входят в чанк страницы, которая их использует. Блоки с состоянием (`FavoriteButton`, `FollowButton`, `LikeButton`, `SaveButton`, `PostCard`, `AiTeaser`) экспортируются отдельно: `@/features/actions` (прямой импорт, если блок нужен сразу) и `@/features/lazy` (`FavoriteButtonAsync` и др. через `defineAsyncComponent`: чанк с библиотекой приходит после первого кадра, кнопки на фото абсолютно позиционированы и вёрстку не двигают). Не добавляйте состояние в `@/features/index.ts`.

## Правила

- **Слои идут вниз.** `layout` и `atoms` не импортируют ничего выше; `molecules` собираются из `atoms`; `organisms` — из `atoms` и `molecules`. Витрина импортирует только из `@/design-system`.
- **Один компонент — одна папка.** `UiName/UiName.vue` и рядом `types.ts` с интерфейсом пропсов (`UiNameProps`) и связанными типами. Публичные имена и типы экспортируются из `index.ts` слоя.
- **Стили только через токены.** Цвета, отступы, радиусы — `var(--…)` из `tokens.css`. Тема переключается атрибутом `data-theme` на `<html>` или на любом блоке (`UiThemeScope`). Затемнение поверх фото и под шторкой — `--scrim`, `--scrim-strong`, текст на нём — `--on-scrim`; тень всплывающих слоёв — `--shadow-float`; граница при наведении — `--border-hover`; сдвиг соседей в списке — `--dur-reflow`.
- **Состояния для витрины.** У `UiButton` и `UiInput` есть `previewState` — принудительно показывает hover/pressed/focus; в продукте не используется.
- **Состояния для витрины (продолжение).** `previewState` есть также у `UiTextarea`, `UiRadio`, `UiRatingInput`, `UiListRow` (`hover`/`pressed`/`focus`).
- **Доступность.** Иконочные кнопки требуют `label`; поля получают `id` и `aria-describedby` от `UiField` через слот; вкладки и сегменты управляются стрелками.
- **Данные не в компонентах.** Тексты и списки живут в `showcase/data`, компоненты принимают их пропсами.

## Анимации

Страница `/motion` показывает каждую анимацию с тремя ответами: как часто её видят, зачем она нужна, из чего собрана (инструмент, свойства, кривая, длительность). Внизу экрана панель: замедление ×1/×2/×5 для проверки на глаз и режим «Меньше» — эмуляция `prefers-reduced-motion`.

**Инструменты — от дешёвого к дорогому.** CSS transition и `:active` для кнопок и состояний; Vue `<Transition>` для входа, выхода и переходов между страницами; нативный `<dialog>` для окон и шторок; View Transitions API для смены темы; [Motion for Vue](https://motion.dev) (`motion-v`) только там, где нужны пружины, жесты и анимация раскладки: смахивание, общий элемент между экранами, смена содержимого кнопки, пружинная дорожка в демо прерывания. Добавление и удаление в списке, «подпрыгивание» сердца, вкладки — без библиотеки (`<TransitionGroup>` с FLIP, WAAPI, `clip-path`). Библиотека подключается лениво вместе со страницей `/motion` и в основной бандл не попадает; новые компоненты дизайн-системы в неё не входят вовсе; компонент `m` вместо `Motion`, а набор возможностей (drag, layout) грузится отдельным чанком через `LazyMotion` (`motion/features.ts`). Чанк страницы: 62 → 43 КБ gzip, ещё 21 КБ приходят следом.

**Правила движения.**
- Кривые и длительности — только из `motion.css` (`--ease-out`, `--ease-in-out`, `--ease-drawer`, `--dur-*`). Встроенные CSS-кривые слабые, `ease-in` в интерфейсе не используется.
- Анимируем `transform` и `opacity`. Исключение — раскрывающийся блок (высота), там короткие 200 мс.
- Сначала CSS, затем WAAPI и View Transitions, и только потом библиотека — и только для пружин, жестов и анимации раскладки. Библиотеку всегда через `LazyMotion` и `m`, не через полный `Motion`.
- Вход и выход — `ease-out`, движение по экрану — `ease-in-out`, всё, что нажимают часто, — transition или пружина, а не keyframes.
- Уменьшенное движение — это меньше, а не ноль: смещения и масштаб умножаются на `--motion-distance` (0 при `prefers-reduced-motion`), прозрачность и цвет остаются.
- Наведение красит фон только там, где есть мышь: `@media (hover: hover) and (pointer: fine)`.
- Действия, которые повторяют сотни раз в день или делают с клавиатуры, не анимируются (см. раздел «Где анимации не будет»).

## Плавность на телефонах

Проверять на собранной версии (`bun run build && bun preview`), а не на `bun dev`: в dev-режиме код не минифицирован и идёт HMR. Инспектор Vue включается только явно: `VUE_DEVTOOLS=1 bun dev`.

Что влияло на кадры и как устроено сейчас:
- **Длинная страница.** Разделы `ShowcaseSection` с `content-visibility: auto`: то, что вне экрана, не считается и не рисуется. Страницы монтируют разделы по одному в простое браузера (`shell/useProgressiveMount.ts`), поэтому переход не ждёт отрисовки всего.
- **Переход между страницами.** Шапка и нижняя навигация живут в оболочке и не участвуют в переходе. Анимируется только страница (подвал гаснет вместе с ней): `transform` на предке ломал бы `position: fixed` внутри неё, а слой на всю длину страницы дорог. Прокрутка применяется после появления новой страницы, а не до.
- **Размытие фона.** `backdrop-filter` только на устройствах с мышью; на тач-экранах шапка непрозрачная. У плавающих панелей (нижняя навигация, панель управления анимаций) и у шторок размытия нет.
- **Размер основного бандла.** В `package.json` стоит `"sideEffects": ["**/*.css"]`: компоненты дизайн-системы, которых страница не использует, в основной чанк не попадают (иначе общий экспорт `@/design-system` тянул бы в него всё). Компоненты витрины (`UiToast`, `UiMediaPicker` и др.) грузятся вместе со страницей `/design-system`. Модуль, у которого есть побочный эффект, но нет экспорта (регистрация, глобальный слушатель, `import './x'` ради эффекта), надо перечислить в `sideEffects` того же `package.json`, иначе сборка выбросит его как неиспользуемый.
- **Подвал продукта** — `content-visibility: auto`. Пока открыта шторка, страница под ней не прокручивается.
- **Смена темы.** Круг (`clip-path`) перерисовывает экран каждый кадр, поэтому на тач-экранах по умолчанию затухание (переключается в разделе «Темы»).
- **Замер.** В headless Chrome с замедлением процессора ×4 самый долгий кадр перехода между страницами упал с 333 до 133 мс, а открытие шторки с 83 до 33 мс. Это тест на главном потоке: работу графического процессора и реальные телефоны он не заменяет.

## Что дальше

- Заменить текстовый макет логотипа (`UiLogo`) оригинальным знаком.
- Подключить шрифт локально вместо Google Fonts, если нужен запуск без сети.
- Окна, выпадающие списки и подсказки на странице анимаций — демонстрации движения на нативных примитивах. В продукте их лучше взять из безголовой библиотеки (фокус, позиционирование, доступность), сохранив токены движения.
- Добавить тесты компонентов и линтер, когда определится стек продукта.
