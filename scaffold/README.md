# scaffold — Vue-разметка дизайн-системы «Местами вкусно»

Каркас фронтенда: дизайн-система из `../design-system.html`, разобранная на минимальные типизированные компоненты Vue 3 + TypeScript, и страница-витрина, которая их показывает. Документы в `materials/` рабочей области — источник истины по функциям; здесь только форма, цвет и состояния.

## Запуск

```sh
bun install
bun dev             # http://localhost:5173 — «Система», /motion — «Анимации»
bun run build       # проверка типов (vue-tsc) и сборка
bun run type-check
```

## Структура

```
src/
  main.ts                    точка входа: тема + стили + монтирование
  App.vue                    роутер + переход между страницами
  router.ts                  маршруты: `/` — система, `/motion` — анимации (ленивая загрузка)
  pages/                     страницы: DesignSystemPage, MotionPage
  shell/SiteTopbar.vue       общая шапка: переключение страниц, разделы, тема
  design-system/             сама дизайн-система (не знает о витрине и о продукте)
    styles/                  tokens.css (тёмная и светлая тема), motion.css (кривые, длительности), base.css
    motion/tokens.ts         зеркало токенов движения для JS: EASE, DURATION, SPRING
    icons/shapes.ts          типизированный реестр иконок (IconName)
    types/                   общие типы: ThemeName, SpaceToken, NavItem, ...
    composables/             useTheme (смена темы с переходом), useMotion, useCssToken, useArrowNavigation
    components/
      layout/                UiStack, UiCluster, UiGrid — раскладка
      atoms/                 неделимые элементы: UiButton, UiInput, UiBadge, UiIcon, ...
      molecules/             сборки из атомов: UiField, UiTabs, UiMediaCard, ...
      organisms/             крупные блоки: UiAppHeader, UiTabBar, UiFooter, ...
    index.ts                 публичный API (`@/design-system`)
  showcase/                  страница-витрина (только для просмотра системы)
    components/              обвязка страницы: секция, сцена, образец цвета
    sections/                разделы: цвета, кнопки, поля, карточки, ...
    data/                    типизированные данные для витрины
  motion/                    страница анимаций (`/motion`)
    components/              MotionDemo (карточка: частота, цель, из чего собрано), CurvePlot, панель управления
    demos/                   по одному компоненту на анимацию
    sections/                разделы: токены, кнопки, темы, страницы, окна, списки, жесты, «без анимации»
    composables/             useAnimatedDialog — нативный <dialog> с анимацией входа и выхода
    data/                    типизированные данные страницы
```

## Правила

- **Слои идут вниз.** `layout` и `atoms` не импортируют ничего выше; `molecules` собираются из `atoms`; `organisms` — из `atoms` и `molecules`. Витрина импортирует только из `@/design-system`.
- **Один компонент — одна папка.** `UiName/UiName.vue` и рядом `types.ts` с интерфейсом пропсов (`UiNameProps`) и связанными типами. Публичные имена и типы экспортируются из `index.ts` слоя.
- **Стили только через токены.** Цвета, отступы, радиусы — `var(--…)` из `tokens.css`. Тема переключается атрибутом `data-theme` на `<html>` или на любом блоке (`UiThemeScope`).
- **Состояния для витрины.** У `UiButton` и `UiInput` есть `previewState` — принудительно показывает hover/pressed/focus; в продукте не используется.
- **Доступность.** Иконочные кнопки требуют `label`; поля получают `id` и `aria-describedby` от `UiField` через слот; вкладки и сегменты управляются стрелками.
- **Данные не в компонентах.** Тексты и списки живут в `showcase/data`, компоненты принимают их пропсами.

## Анимации

Страница `/motion` показывает каждую анимацию с тремя ответами: как часто её видят, зачем она нужна, из чего собрана (инструмент, свойства, кривая, длительность). Внизу экрана панель: замедление ×1/×2/×5 для проверки на глаз и режим «Меньше» — эмуляция `prefers-reduced-motion`.

**Инструменты — от дешёвого к дорогому.** CSS transition и `:active` для кнопок и состояний; Vue `<Transition>` для входа, выхода и переходов между страницами; нативный `<dialog>` для окон и шторок; View Transitions API для смены темы; [Motion for Vue](https://motion.dev) (`motion-v`) только там, где нужны пружины, жесты и анимация раскладки: смахивание, общий элемент между экранами, смена содержимого кнопки, пружинная дорожка в демо прерывания. Добавление и удаление в списке, «подпрыгивание» сердца, вкладки — без библиотеки (`<TransitionGroup>` с FLIP, WAAPI, `clip-path`). Библиотека подключается лениво вместе со страницей `/motion` и в основной бандл не попадает; компонент `m` вместо `Motion`, а набор возможностей (drag, layout) грузится отдельным чанком через `LazyMotion` (`motion/features.ts`). Чанк страницы: 62 → 43 КБ gzip, ещё 21 КБ приходят следом.

**Правила движения.**
- Кривые и длительности — только из `motion.css` (`--ease-out`, `--ease-in-out`, `--ease-drawer`, `--dur-*`). Встроенные CSS-кривые слабые, `ease-in` в интерфейсе не используется.
- Анимируем `transform` и `opacity`. Исключение — раскрывающийся блок (высота), там короткие 200 мс.
- Сначала CSS, затем WAAPI и View Transitions, и только потом библиотека — и только для пружин, жестов и анимации раскладки. Библиотеку всегда через `LazyMotion` и `m`, не через полный `Motion`.
- Вход и выход — `ease-out`, движение по экрану — `ease-in-out`, всё, что нажимают часто, — transition или пружина, а не keyframes.
- Уменьшенное движение — это меньше, а не ноль: смещения и масштаб умножаются на `--motion-distance` (0 при `prefers-reduced-motion`), прозрачность и цвет остаются.
- Наведение красит фон только там, где есть мышь: `@media (hover: hover) and (pointer: fine)`.
- Действия, которые повторяют сотни раз в день или делают с клавиатуры, не анимируются (см. раздел «Где анимации не будет»).

## Плавность на телефонах

Проверять на собранной версии (`bun run build && bun preview`), а не на `bun dev`: в dev-режиме код не минифицирован и идёт HMR. Инспектор Vue включается только явно: `VUE_DEVTOOLS=1 bun dev`.

Что влияло на кадры и как устроено сейчас:
- **Длинная страница.** Разделы `ShowcaseSection` с `content-visibility: auto`: то, что вне экрана, не считается и не рисуется. Страницы монтируют разделы по одному в простое браузера (`shell/useProgressiveMount.ts`), поэтому переход не ждёт отрисовки всего.
- **Переход между страницами.** Шапка живёт в оболочке и не участвует в переходе. Анимируется только страница: `transform` на предке ломал бы `position: fixed` внутри неё, а слой на всю длину страницы дорог.
- **Размытие фона.** `backdrop-filter` только на устройствах с мышью; на тач-экранах шапка непрозрачная. У плавающей панели управления размытия нет.
- **Смена темы.** Круг (`clip-path`) перерисовывает экран каждый кадр, поэтому на тач-экранах по умолчанию затухание (переключается в разделе «Темы»).
- **Замер.** В headless Chrome с замедлением процессора ×4 самый долгий кадр перехода между страницами упал с 333 до 133 мс, а открытие шторки с 83 до 33 мс. Это тест на главном потоке: работу графического процессора и реальные телефоны он не заменяет.

## Что дальше

- Заменить текстовый макет логотипа (`UiLogo`) оригинальным знаком.
- Подключить шрифт локально вместо Google Fonts, если нужен запуск без сети.
- Окна, выпадающие списки и подсказки на странице анимаций — демонстрации движения на нативных примитивах. В продукте их лучше взять из безголовой библиотеки (фокус, позиционирование, доступность), сохранив токены движения.
- Добавить тесты компонентов и линтер, когда определится стек продукта.
